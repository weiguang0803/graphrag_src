GraphRAG 是由微软研究院在 2024 年提出的一种基于知识图谱的检索增强生成方法。它的核心思想是：先用大语言模型从文档中抽取实体和关系，构建一张知识图谱，再通过社区发现算法（如 Leiden 算法）对图谱进行分层聚类，最后为每一层社区生成摘要，从而在回答全局性、跨文档的问题时显著优于传统 RAG。
传统 RAG（Retrieval-Augmented Generation）的工作流程是：将文档切分为若干文本块（chunk），对每个 chunk 做向量化并存入向量数据库，用户提问时把问题也向量化，检索出最相似的若干个 chunk，再把这些 chunk 作为上下文拼进 Prompt 交给大语言模型生成答案。这种方法的优点是简单、实时性好，缺点是只能做"片段级"检索，难以回答需要跨多个文档综合推理的问题。
GraphRAG 的索引阶段成本较高。它需要为每篇文档的每个 chunk 调用大语言模型抽取实体和关系，然后再调用模型为每一个社区生成摘要。对于一个包含数十万 token 的语料库，索引阶段的 API 调用费用可能高达数十甚至上百美元，且耗时从几十分钟到数小时不等。这是 GraphRAG 在生产落地时面临的最大挑战之一。
为了降低 GraphRAG 的成本，社区涌现了多种改进方案。LightRAG 通过简化图构建流程、支持增量更新和合并去重，将索引成本压缩到原来的几十分之一。nano-graphrag 用不到 1000 行代码复刻了微软 GraphRAG 的核心流程，方便开发者阅读和改造。KAG（Knowledge Augmented Generation）则强调知识表示与逻辑推理的结合，在法务、医疗等专业领域表现出色。
ChromaDB 是一个轻量级的本地向量数据库，适合个人开发者和小型项目快速搭建 RAG 原型。它支持按集合（collection）管理文档，提供余弦相似度和欧氏距离等多种检索方式，且无需单独部署服务，pip install 即可使用。对于大规模生产环境，Milvus 和 Qdrant 是更常见的选择，它们支持分布式部署、海量数据和高并发查询。
知识图谱与大语言模型的结合是当前 AI 领域的重要研究方向。除了 GraphRAG，还有多种相关技术路线。HippoRAG 模仿人类长期记忆的更新机制，将文档检索与大模型推理深度融合。RAPTOR 通过递归式摘要树来组织文档层次结构。KGP（Knowledge Graph Prompting）则直接用图神经网络增强 Prompt 的上下文表达。这些方法各有侧重，但共同目标是突破传统 RAG 在全局理解、多跳推理和知识关联方面的瓶颈。
阿里云百炼平台提供了通义千问系列大模型的 API 服务。其中 qwen3-max 是该系列的旗舰文本生成模型，在代码、推理、Agent 工具调用等任务上达到业界领先水平。开发者可以通过 OpenAI 兼容接口直接调用，只需将 base_url 指向 dashscope.aliyuncs.com 的兼容模式地址，并配置对应的 API Key 即可。该平台还提供 text-embedding-v3 等向量化模型，可用于构建 RAG 系统。
硅基流动（SiliconFlow）是一个国产大模型云服务聚合平台，提供包括 BAAI/bge-m3 在内的多种开源模型的 API 接口。BGE-M3 是由北京智源人工智能研究院（BAAI）开发的多语言嵌入模型，支持超过 100 种语言，最大输入长度 8192 token，输出向量维度为 1024。该模型在硅基流动平台上对个人开发者免费开放，非常适合中文 RAG 场景下的文档向量化需求。
